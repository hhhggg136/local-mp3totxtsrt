# 本地纠错学习：内存验证

验证日期：2026-10-11。Apple silicon Mac，24 GiB RAM，macOS 26，Swift 6.3.3。优化构建。

## 实测结果

| 指标 | 实测 |
|---|---:|
| 同一测试程序空运行峰值 RSS | 6.42 MiB |
| 学习压力测试峰值 RSS | 17.72 MiB |
| 两次进程峰值之差 | 11.30 MiB |
| 第 1 批结束后的驻留内存 | 16.28 MiB |
| 第 20 批结束后的驻留内存 | 17.27 MiB |
| 最后 5 批结束后的驻留内存范围 | 17.27–17.27 MiB |
| 测试数据库大小 | 0.67 MiB |

使用**合成 SRT 测试数据**，不是用户字幕：构建 5000 条不同的短词纠错，连续导入 20 个版本；每批读取界面用的 200 条记录，并生成受长度限制的识别提示。对照空运行和压力运行的 `/usr/bin/time -l` 最大 RSS；逐批通过 Mach API 读取同一学习进程的当前驻留内存。

词库满 5000 条后，已存在词语仍能更新计数。20 批全部执行完成；最后 5 批内存稳定在上表范围内。本轮学习增量低于预设的 50 MB 目标。

## 结论边界

这是学习核心的进程级测试，**不包含图形界面、语音识别模型或 GPU 总内存**。两次峰值之差是实验对照值，不是内存分配的精确归因。20 批结果不能证明长期运行永远不增长。

没有重新训练模型，未加载额外大语言模型。没有独立人工标注验证集，因此本报告不证明识别准确率改善。

## 复现

```bash
bash scripts/test.sh
bash scripts/check-memory.sh
```

脚本在系统临时目录建立独立 SQLite 数据库，完成后清理；详细原始测量输出保存在 `.local/learning-memory-result.json` 和 `.local/learning-memory-*-time.txt`，不上传个人数据。

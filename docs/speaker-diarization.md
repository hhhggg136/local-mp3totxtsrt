# 本地说话人区分 0.6.0

## 功能及边界

入口：工作台导入音视频和对应 SRT → 说话人 → 本地分析。按原始字幕区间取声音，不使用重排后的时码。A/B/C 按原素材首次出现顺序编号，可批量改名、手动新增和逐句改归属。修改元数据，不直接往正文插入名字；导出可选择带名字或纯对白。

使用每句 0.8–3 秒的窗口，长句最多 3 个。CAM++ 输出归一化 192 维向量，结合窗口一致性、余弦相似度和间隔形成候选。自动模式使用有限个中心、两遍分配；指定人数时使用确定性球面 k-means，最多 8 人。很短、很轻、声音变化大或归属不明确时保留待确认，自动候选也需人工核对。不会通过字幕内容、句子轮次、音调规则假装识别说话人。

不自动重切一条 SRT 内不同人的文字，不做声源分离，不识别真实身份，不跨视频记人。游戏人物配音与玩家语音可能都被归入候选，变声器、同音色、BGM、语音压缩及重叠会分错。模型主要覆盖中英声音条件，其他语言与实际游戏直播尚未取得本次独立准确率证据。首次真实游戏素材有待用户提供。

## 状态与资源

`SpeakerTypes.swift` 保存说话人名字、对白 UUID → 归属及人工/自动说明；无嵌入向量进入项目或词库。修改名字/单句只保存有限逆操作。分析成功建立新基线并清空撤销历史，界面提前确认；失败/取消保留旧数据。schema 1 旧项目可读取；含说话人数据为 schema 2，旧版拒绝打开。保存完整元数据和一份 `.bak`，素材只读。

Swift AVFoundation 按源 PTS 流式生成 16 kHz 单声道 PCM16 临时文件，保留领先/中间/结尾间隙；临时文件约 32 KB/秒，放在系统临时目录。C++ 子进程只读取每个短窗口，2 个 CPU 推理线程；不载入完整音频、不启动 Whisper。分析完毕或取消时子进程退出，临时音频/向量清理。字幕上限 10000 条，分析素材上限 24 小时，候选最多 26 个。窗口与系统框架可能保留缓存，不能保证 RSS 全部立即归还。

### 内存口径

24 GiB Apple silicon Mac，macOS 26.6.2；MiB = 1048576 字节。不含 Whisper 识别模型。

| 样本/流程 | 模型进程峰值 RSS | 父子进程同刻 RSS 合计峰值 |

| 32 秒公开声音，纯处理程序 | 113.1 MiB | 未单独采样 |
| 334 秒真实视频，纯处理程序 | 111.8 MiB | 未单独采样 |

完整窗口测试模型退出后，主窗口 RSS 约 227.8 MiB；模型子进程不存在。RSS 合计按 `ps` 同一采样时刻计算，可能重复计算共享页；它不是 Physical footprint，不能和 0.5.0 报告的物理占用峰值直接相减。当前测试 Mac 的结果不代表所有素材/编码/声道与机器的上限。

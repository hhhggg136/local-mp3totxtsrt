# 0.2.1：字幕跨停顿提前出现的修复

验证日期：2026-10-13。macOS 26 / Apple silicon。

## 已确认原因

0.2.0 使用 whisper.cpp 内置 VAD：移除原音频中的静音，把人声拼接后识别，再通过映射表还原整句起止时间。整句可能覆盖多个分离的人声区间，或者时间端点落在被压缩的停顿处。直接把这些整句端点导出，导致下一句在角色开口之前显示，上一句则一直跨越停顿。

在保留的旧输出中已找到跨度很长的合并字幕；用两段授权对白摘录和中间人为插入的 4 秒数字静音进一步复现。这不是把全部字幕统一延后若干毫秒就能修好的问题。

## 修复方式

- 在原始 16 kHz PCM 上检测人声，不把静音移除后拼接。
- 人声检测使用 60 秒窗口，前后各 2 秒上下文；原始采样位置始终保留。只合并重叠的人声区间以消除窗口重复，不填补不相交区间之间的停顿。
- 模型一次加载，按独立人声区间识别；连续长人声最多按 15 秒分开处理。
- 识别可以读取相邻的少量声音上下文，但字幕起止只使用原素材中检测到的人声边界，不包含这些额外上下文。
- 每段不继承上一段的识别文本，已确认词库仍作为显式提示提供。
- JSON 保留 `speech_regions`，方便核对；TXT、SRT 和学习基准采用同一套时间码。

## 验证结果

| 样本 | 旧版 | 0.2.1 |
|---|---|---|
| 明确的 4 秒数字静音：3.76–7.76 秒 | 下一句从 5.80 秒开始，位于静音中 | 下一句从 7.87 秒开始，静音期间留空 |
| 跨 60 秒检测窗口的静音：57.76–61.76 秒 | 用于新增回归覆盖 | 下一句从 61.79 秒开始，无累计偏移 |

四项原始区间合并、裁剪及偏移检查通过；15 项既有词库检查通过；旧识别结果读取的 3 项检查也通过。两份授权真实素材（约 84 秒和 334 秒）成功生成字幕，所有有效字幕区间均落在检测到的原始人声区间，时间码为正且未超过素材长度。两份原素材 SHA-256 均保持不变。

最终两次命令行识别作业 `/usr/bin/time -l` 报告的峰值 RSS 约 853.6 MiB 和 859.8 MiB。这不代表整个 GUI 与所有 GPU 内存的总和。

## 限制与使用

这是人声区间校准，并非逐字强制对齐。边界依赖 Silero VAD：轻声、音乐、重叠说话、极短应答仍可能漏检或偏移；按停顿拆开后，短片段的识别文字也可能变化。本轮没有人工逐字和逐帧标注，不能据此声称所有素材都达到固定毫秒精度或文字准确率提高。

旧字幕和个人词库不被修改。重新打开 0.2.1，重新识别素材即可生成修正版。新校对应使用新输出中的 `学习基准.srt`；旧版基准仍适用于它自身对应的校对版。

普通检查：`bash scripts/test.sh`。真实引擎回归：按 README 的 `timing_integration.py` 命令提供授权的 PCM16 WAV 和两段对白区间；加 `--lead-in 56` 覆盖跨检测窗口场景。测试只创建本地副本，不上传素材。
